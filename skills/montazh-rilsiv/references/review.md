# Reel Review page

A private page on the person's claude.ai account where they approve the edit before anything renders: cuts, graphics, captions, sound and colour, then a draft preview with timestamped notes. It needs Claude Code with Artifacts (the `Artifact` and `ArtifactData` tools) and the `db` + `assets` capabilities. If those aren't available, review in chat instead (rough-cut lines, then a card list) and skip this file.

## One time per reel

1. After transcribing and cleaning audio, run `python3 scripts/tighten.py <reel> --detect` so the "um"s are found (it writes `fillers.json`; without it the page shows no grey "um"s and none get cut). It reads the "um"s from the Scribe transcript, so run it after `transcribe.py`. If it prints `FILLERS NOT DETECTED` (exit code 3), transcript.json is missing: transcribe first. Then write `proposal.json` in the reel folder (format in the header of `scripts/review_sync.py`): the kept lines, accent words, and every graphic anchored to a spoken word with its `place` box and sound.
2. `python3 scripts/review_sync.py export <reel> proposal.json <out>` → `<out>/reel.json` (also saved as `<reel>/review_reel.json`).
3. Make the assets (keep them light, `nice -n 15`):
   - a 540x960 source proxy of `raw.mov` with the **cleaned** `voice.wav` as its audio: `bash scripts/page_proxy.sh <reel>/raw.mov <reel>/voice.wav <out>/src.mp4` (media engine on a Mac, bitrate sized to stay under the 20 MB upload limit, so it never has to be made twice). Start it in the background right after `clean_audio.sh`. The raw phone audio is ~20 dB quieter, so a proxy with it makes the voice sound broken
   - per graphic: `thumb_<id>.jpg` (180x320 frame at its anchor word) and `img_<id>.jpg` (its screenshot/image, 480 wide)
   - **storyboard** (every time graphics are proposed): `python3 scripts/storyboard.py <reel>` → `<reel>/storyboard/story_<id>.jpg`, one 540x960 still per graphic: their own frame at that moment with that very card on it (brand, tested placement), ~10 s a card, no render. Plus `hook_<n>.jpg` for each `"hookOptions"` text in proposal.json. Upload them and set each board item's `storyUrl` and `hookOptions: [{text, img}]` in `reel/current`: «Графіка» then shows the real look (tap = big) instead of a frame with a text box, and the hook as pictures A/B/C next to the field for their own. Look at every still before sending the link; a still that shows something wrong is fixed in proposal.json first.
   - `audio_original.mp4` / `audio_cleaned.mp4` (same 10 s), `colour_before.jpg` / `colour_after.jpg` (same frame, grade applied), `sfx_<name>.mp4` for each sound
   - the brand's caption fonts (.otf/.ttf/.woff2) **only if the person owns them and the page stays private**
   Asset uploads accept mp4 (audio too), jpg/png, fonts; not m4a or wav.
   The page takes its look from `reel.json` `theme` (brand.json colours; an optional brand.json `"page"` block overrides any token, e.g. their website's background, accent, grid and glows, and `label` for the line above the title).
4. First time only: publish `review/reel-review.html` with `files: {"core.js": "review/core.js", "app.js": "review/app.js"}` (the page is markup + styles; its logic is app.js, the shared timing maths core.js: republish all three together), `capabilities: {"db": {"rules": [{"path": "reel", "write": "admin"}, {"path": "builds", "write": "admin"}]}, "assets": {}, "comments": {}}` (`comments` is what lets the big button wake Claude with a «Send to Claude» comment; without it the page always says «Claude зараз не на зв'язку» and they have to type the word in chat. Only editors can change the reel data and the preview; anyone you share it with at Contributor level can still record review decisions), `icon: "video"`. Later reels reuse the same page URL.
   **«Мої файли» (db `library/files`):** their reusable photos, stickers and logos live on the page across reels. On first publish, and whenever `~/reels/assets/elements` gets new files, upload those PNGs (`asset: true`, up to 25 per call) and write `library/files` = `{items: [{id, url, name, kind: "image"}], updatedAt}`. Read it first and merge: keep every item they saved from the page (the «Зберегти в мої файли» tick), add only new names, never drop theirs.
5. Upload the assets to the page (`asset: true`, up to 25 per call), then write `reel/current` = `reel.json` plus `srcUrl`, per-graphic `thumbUrl`/`imgUrl`, `assets` {audioOriginal, audioCleaned, colourBefore, colourAfter, sfx{name:url}}, `fonts` {body, accent}. Delete `review/current` and `builds/latest` from the previous reel (ask first if they hold notes).
6. Send the link. Tell them: type the hook and CTA in the fields on «Графіка» (or approve yours), tap words to cut, use the «Накладення» tab to add their own photo/video at the current rough-cut moment and drag it into place and pull its corner to any size, sticker-small up to full screen (or tick «На весь екран»); effect: soft, slide, polaroid, glass, zoom; up to 20 MB; or pick one from «Мої файли», or add text; tick «За мною» to put it behind them), tap ⏸ / grey "um"s to keep them, Play rough cut to watch the live cut, then Build preview.

## The big button and the steps (no chat words needed)

The page shows steps (1 their edit → 2 Claude's proposals → 3 draft → 4 final) and one big button at the bottom. Each press saves a request in their review doc and sends Claude a «Send to Claude» comment on the artifact, which wakes this session while the artifact's watch says "auto-replies armed" (`ArtifactComments action: "watch"` lists it). The comment text starts with ▶ and names the step; treat it exactly like the chat word:
- `graphicsRequest` / «графіка» → round 2 below. When the proposals are on the board, write `reel/current` with `claudeRound` = previous + 1: the page reloads it in place, jumps to «Графіка» and shows a banner (no refresh needed).
- `buildRequest` / «збери чернетку» → "When they say build preview".
- `fixRequest` (revisions marked `sent`) / «виправ нотатки» → act on those revisions, re-render, new `builds/latest` with `fixedFor` = `fixRequest.at` (the decisions hash may not change, so this is how the page knows the notes were answered).
- `finalRequest` / «фінал» → QA, deliver, covers only if brand.json `covers` isn't false; then `builds/latest` gets `final: true` (step 4).
Reply in the comment thread in one line («Взяв, роблю пропозиції, ~10 хв») and resolve it when done. If no session is listening the page tells them to type the word in chat instead.

## «Меню ефектів» on their face («Ефекти» tab)

Every usable effect (Claude's suggestions and «Тільки вручну») as a 3 s clip on THEIR video in their brand, with a filter,
search and a basket «Мій вибір». On their first reel start `python3 scripts/menu_previews.py <reel>` in the background
right after the cut (~40-60 min, resumes; order: manual, caption styles, suggested). Upload `<REELS_HOME>/menu/*.mp4`
(25 per call) and map name → url in `<REELS_HOME>/.motion_previews.json`; re-export so `reel.json` "manual" carries them
(items with no clip yet say «прев'ю ще готується»). Every menu effect has a fixed number (catalog `"no"`, given once by
`review_sync.manual_effects`, new effects get the next one, never renumbered): the page shows it on each card, finds it in
search, and on «Ефект на конкретну секунду» a typed number becomes `№12 <name>: <ua>` in the request. When they name a
number in chat («постав 12 на 0:05»), look it up in the catalog by `"no"`.
**Once per person, never per reel.** The clips only show what an effect roughly looks like, so they are made on the first
reel and kept: `<REELS_HOME>/menu/` + `.motion_previews.json` serve every later reel (export reads them). On a later reel
do NOT run menu_previews.py again; only when the catalog gained effects with no clip, run it once more (it skips every clip
that exists and renders just the new ones), upload those and add them to the map. A new review page means re-uploading the
saved clips, never re-rendering them. Their basket comes back on import as `MENU PICKS:` (edit.json
`menu_picks`): put every picked effect in the plan on a line it fits, and say which one had no line.
«Подачі голови» (`head-*`, №299-309) are in the same menu; their clips come from `menu_previews.py --only heads` (their own
first words, frames of their reel as the photos, ~2 min for all 11). A person whose menu was made before 2026-10-23 has no
clips for them yet: run that once, upload the 11 and add them to the map. A head layout on the board is a full-frame card
(`place` `[0, 0, 1080, 1920]`), so the page shows its storyboard still and never moves it.

## «Стиль монтажу» examples (step 1)

The tab shows every saved style as a looping example (style/list `url`) plus «Тільки бренд» and «Без стилю: мікс ефектів»,
so they pick by look, not by name. Those two need their own examples, made once per person on their own video: brand = a
~12 s draft (`style: "brand"`, the hook title, one camera move, one brand panel such as `push`), mix = ~1.3 s cuts of 8-9
different effects from a mix draft joined into one clip. Upload them and put the urls in
`<REELS_HOME>/.motion_previews.json` as `"style:brand"` / `"style:mix"`: `review_sync.py export` passes them as
`stylePreviews`. Text cards (the hook first) can be dragged on the video («Перемістити»): the review doc keeps
`board.<id>.place` and `import` writes the card's `x` / `y`.

Saved styles' own examples («Мої стилі», step 1 «Стиль монтажу»): `python3 scripts/style_examples.py` renders ~10 s per style on the lab clip (hook, camera move, the style's graphic, then captions), ONCE per person; re-run with `--only <style>` after a style changes, upload, put the urls in `styles/list.json` and db `style/list`.

## «Стиль» tab (their style, in rounds)

The page also holds the style lab: db `style/round` (written by Claude: the round's sections and variants with their mp4/poster urls) and `style/votes` (their verdicts, notes and references: reel links and uploaded files). It works with or without a reel loaded. db `style/list` (from `~/reels/styles/list.json`) feeds the «Стиль монтажу» buttons on «Графіка»: their pick is `style` in the review doc (part of the decisions hash) and `review_sync.py import` turns it into `<reel>/style.txt`. Under it, «Швидкість руху графіки» (Повільніше x0.75 / Як у стилі / Швидше x1.3) is `speedMul`; import prints `MOTION SPEED` and writes edit.json `motion_mul`, which build_reel multiplies into the style's speed. «Змінити» on a card now asks for a note before «Готово → Claude» / «Зібрати чернетку» (they can still send without one: then ask in one line what to change instead of guessing). The «Готово → Claude» button there sends a «Send to Claude» comment naming the round. Everything else (making rounds, reading verdicts, writing styles) is in `references/style-lab.md`.

## Face, captions and «За мною»

- Before `export`, run `python3 scripts/face_box.py <reel>`: OpenCV (installed by doctor.sh in ~/reels/.venv) finds the face on 12 frames and writes `<reel>/face.json`; `export` puts it into reel.json as `face`. Without it nothing is moved.
- `core.js` `layout()` moves every graphic that would cover the face or the captions: below the chin, or above the head, inside the frame Instagram leaves clear; when nothing fits, the captions step aside while that card shows (`quiet` in edit.json). The page marks these «відсунуто від обличчя»; `review_sync import` writes the new `y` / `box`.
- Captions: on «Субтитри» they pick «Над головою / Під підборіддям / Внизу» or drags a caption on the player; it is saved as `capY` in their review doc and goes into edit.json as `caption_y`.
- Text look: «Вигляд субтитрів» (on «Субтитри») and «Вигляд хука» (under the hook field) set colour or gradient, outline (slider), shadow strength and softness, a box under the line or each word (colour, transparency, corners), the accent word («Колір / Плашка / Підкреслення / Велике / Ехо», two alternating colours) and, for the hook, the second line's colour and the accent font. Saved partial in `look` {cap, hook, keep}; `review_sync import` merges it over brand.json `text_look` into edit.json `text_look` (prints `TEXT LOOK`), and «Робити так у всіх наступних рілсах» (`keep`) writes it to brand.json `text_look`. Put `look: brand.text_look` in `reel/current` (export does it) so the page starts from their saved look. build_reel.py draws it with the page's numbers (`look_run`, `look_bg`).
- **Hook and CTA, full control:** picking either on the timeline makes it draggable right on the video (`board.<id>.place`, CTA too: `board.cta.place`); «Вигляд» for both = «Скільки рядків» 1-4 (re-splits the words with «/»), align, size, per line font / colour or gradient / outline / box, shared shadow (`look.hook` / `look.cta`, build_reel draws a CTA with `text_look.cta` like the hook, else the brand pill). Small screens: steps, then the video, then timeline + the picked element; style below.
- **Step 2 is one place:** style (collapsible) → timeline → the picked element's panel (`#insp`: its storyboard still, Залишити/Змінити/Прибрати + note, «Початок ◀ word ▶», «Тривалість − +», ▶ Дивитись, Перемістити, За мною; the hook's text/A-B-C/look and the CTA's text live inside the hook's / CTA's panel, «+ CTA» is a dashed block on the timeline) → «Нарізка» notes → «Усі елементи списком» (collapsed; a card there selects that element).
- **Таймлайн** (on «Графіка» only, step 2: before Claude's proposals it would hold just the hook): every graphic as a block on its track (Хук і CTA / Від Claude / Твоє, captions for reference). Drag = move: it re-anchors to the nearest kept word (`board.<id>.w0`, overlay/effect `w0`), so later cuts keep it on its words; edge = length (`board.<id>.dur`, overlay/effect `dur`, CTA `cta.dur`); tap + ✕ = remove (board `state: "d"`, overlays/effects deleted). core.js `graphics()` applies them, so import needs nothing new; the draft hash changes like any decision.
- **«Знайти» on «Накладення»**: they pick photo / GIF / full-screen video / meme, writes the meaning, presses «Знайти варіанти» (a «Send to Claude» comment «▶ Знайди варіанти…»; review doc `finds: [{id, kind, meaning, w0, at, picked: [], memeText?}]`). Claude answers with 10-15 options in `reel/current.finds[<id>]` (SKILL.md, find_options.py). Her picks turn into overlays at once (`fromFind`, `findOpt`, `file`): GIF and video one choice, photos several staggered by ~4 words, a meme one template + their text.
- «Мої кольори»: every colour picker shows the brand colours plus their own up to 10 swatches in all (at least 3 of theirs; db `library/colors` = `{items: ["#RRGGBB"]}`, newest first, the oldest drops out; brand colours never do). A colour they pick with the custom picker is kept there for every reel; the page writes it, Claude only reads it.
- «За мною» on any graphic on «Графіка» sets `board.<id>.behind`; the card renders behind the person (cut-out on those seconds only). Behind the body it would not show, so `layout()` lifts it into the background above the head (big words/hook tuck ~35% behind the hair, lists and cards ~8%; too tall → shrunk with `zoom`), and `capsAround()` drops the captions that would overlap it under the chin for those seconds (per-caption `y` in edit.json).

## Colour and sounds on «Звук і колір»

- **Colour**: iPhone-style sliders (exposure, highlights, shadows, contrast, brightness, saturation, vibrance, warmth, clarity, sharpness, each -100..100). The page previews them with WebGL using `core.js` `gradeParams`; `review_sync.py import` writes `<reel>/grade.cube` and the ffmpeg chain into `edl.json` `grade`, and `cut.py` applies it. Untouched = no grade.
- **Sounds**: each sound on a graphic can be switched off or replaced from the library (`sfxSwap` in the review doc). The library lives in db `library/sfx` = `{items: [{name, label, cat, url}]}` and on disk in `sfx/` of this skill (copied into `~/reels/assets/sfx`; `build_reel.py` takes sounds from both, the person's own folder wins). First setup: upload every `sfx/*.wav` as an audio-only mp4 (`asset: true`) and write `library/sfx` with those urls, labels and categories from `sfx/library.json`.
- Their own sounds: a recording with sound, silence, sound… → `python3 scripts/slice_sfx.py <video> [names.txt]` cuts it into separate sounds in `~/reels/assets/sfx`.

## Effects they ask for («+ Додати» on the step-2 timeline)

**The hook is set on step 1** («Хук і субтитри», first block): A/B/C or her own text, every line's font / colour / outline / box, «Перемістити хук на відео». It is baked into the step-2 video and is not edited on step 2 (the timeline only shows it). The page follows three steps: **1 «Монтаж»** = cuts, their own photos / videos / GIFs («Накладення»), captions, sound, style; no effects there (the «Ефекти» tab is hidden). **2 «Графіка»** = the video already cut WITH Claude's effects and captions (`graphics_preview.py`); on the timeline they remove what they don't want and add effects with «+ Додати»: the playhead's second, then the library («Мої марки» first, then every menu effect with its number and clip), or «Описати своїми словами», or a jump to «Накладення» for a photo / GIF. Each pick lands as an effect block on the «Твоє» track (`effects` in the review doc: `{id, w0, at, dur, text}`), which they drag and stretch like any block. **3 «Чернетка»** = one render with all of it, then notes or the final.
On «Зібрати чернетку» every effect comes out of `import` as `EFFECT REQUESTED @ cut …` (`№<no> <name>: <ua>` for a library pick, `★ моя марка <key>` for a stamp, or their words): build each one at that moment for that long without asking, with the line's `| sound:` (a library sound name, or `off` = no sound; set it as the card's `sfx`) (catalog name → `motion` card with their words from that line (an `fx-…` name → an `fx` card, «Ефекти Vibha» in motions.md); stamp → its saved settings; words → the closest catalog motion, else a `custom` motion).

On «Ефекти» they pick a moment of the rough cut, describe an effect (a HyperFrames catalog name such as `count-up`, or their own words) and can attach photos/videos for it. The «Відкрити бібліотеку ефектів» button opens the catalog: the public one at hyperframes.heygen.com/catalog, or their own gallery page: set `libraryUrl` in the db doc `library/files` (works for every reel) or brand.json `"page"` `"library"`. `review_sync.py import` and `overlays` print each as `EFFECT REQUESTED @ cut …s for …s, from word "…": <text> | files: <name> -> DOWNLOAD asset <id> into <reel>/effects`.
- Download each file with `Artifact` `action: "read"`, `path` = the asset id, `out_dir` = `<reel>/effects`.
- A catalog name: if it's in `references/motion_catalog.json` as ready, a `motion` card at that moment with their files as `images`/vars. Not there yet: add and test it first («Adding more» in `references/motions.md`). Their own words: build it as a `custom` motion (see SKILL.md «Own motion design on phrases»).
- It goes on «Графіка» as their item (like an overlay), so plan your cards around it. If a description is unclear, ask one short question before building.

## Two rounds: their overlays first, then Claude's graphics

Their own photos/videos come before Claude's cards and motion, so the graphics plan goes around them instead of under them.
1. **Round 1 (cuts + overlays).** Export with only the hook card on the board (`"cards"` in proposal.json = the hook alone), send the link and tell them: cut on «Нарізка», then on «Накладення» put their own photos/videos where they want them (size, effect, drag the box on the player), then write «графіка». If they have nothing to add, they write «графіка» straight away.
2. **On «графіка»: the cut video first (step 2 is «Нарізка і графіка»).** `ArtifactData get review/current`, then right away: `review_sync.py import` (writes edl/edit, prints `STYLE`), `snap_joins.py`, `REEL_PREVIEW=1 cut.py`, and a 540p copy of `master.mp4` via `bash scripts/page_proxy.sh <reel>/master.mp4 - <out>/cut_540.mp4` (no graphics, no captions: the page draws their captions and graphic boxes on top) → upload → `ArtifactData set builds/cut` = `{url, cutHash: <review.graphicsRequest.cutHash>, at, cutDur}` (batch reels: `builds/<id>-cut`). The page plays it on step 2 and they leave «Нотатка на цю секунду» on it (`cutNotes`, cut seconds; import prints `CUT NOTE`): fix those in the edl before the draft. While it cuts, plan the graphics:
   then `python3 scripts/review_sync.py overlays <reel> <review.json>`: it lists every overlay they placed (cut and source time, the word it hangs on, its box). Plan the cards and own motion around those: no card or motion in the same moment AND the same area as one of their overlays, nothing at all during a full-screen one, and nothing that repeats what their picture already shows. Write proposal.json with the hook + the new cards, re-run `export` (word indices don't change, so their cuts, captions and overlays stay valid), upload the new thumbs, and `ArtifactData update reel/current` with the new `board` (keep `srcUrl`, `assets`, `fonts`, `theme`). Any `CONFLICT` line from `overlays` must be fixed before they see the page.
   **Then render it, don't show boxes:** placeholder boxes make the whole picture hard to judge. Download every overlay asset
   first, write the new board with `ArtifactData`, read the review doc again (so it has the board), then
   `python3 scripts/graphics_preview.py <reel> <review.json>`: import + cut (cached) + precheck + a 540p draft with every graphic
   and the captions (the hook stays out until they pick its text). Upload `gfx_preview.mp4`, put its url into
   `gfx_preview.json` and `ArtifactData set builds/cut` (batch: `builds/<id>-cut`) with it (`rendered: true`, `ids` = the
   graphics baked in). The page plays that video on «Графіка» and draws only what isn't in the picture yet; a graphic they
   remove is marked «Прибрано». Storyboard stills are only for the hook options now (and for a quick look yourself first).
3. **Round 2.** Open the page and tell them in two lines: the video on «Графіка» already has the effects; on the timeline they
   remove what they don't want, add their own (photo, GIF, «Знайти», or an effect from the library on «Ефекти» by number at a
   second), then «Зібрати чернетку». Additions and removals go into that one draft: the last render before the final.

## Several reels at once (3-5 clips in one go)

The same page holds a batch: a «Рілс» picker appears at the top when `reel/index` lists more than one reel. Each reel keeps its own decisions and preview.
- **Docs per reel:** `reel/<id>`, `review/<id>`, `builds/<id>`, with `<id>` = the reel folder name (e.g. `2026-10-14-hooks`). `reel/index` = `{items: [{id, title, status}]}` in the order they will review them; `status` is a short Ukrainian word the picker shows («готується», «перевіряєш», «рендериться», «чернетка готова», «фінал»). One reel on its own keeps using `reel/current` / `review/current` / `builds/latest` and no index; when a batch starts, delete `reel/index` items from the previous batch first (ask if their review docs hold notes).
- **Prepare in order, first one fast.** Make a folder per clip. Do reel 1 end to end (transcribe, clean, `tighten --detect`, proposal with the hook only, export, assets, `reel/<id>`, add it to `reel/index`) and send the link at once. Then prepare 2..n one by one while they review (`nice`, never two transcriptions at the same time); after each, add it to `reel/index` (the page tells them «наступний рілс готовий») and say it in one line.
- **Her steps per reel stay the same:** cuts + overlays → «графіка» → your cards → «збери чернетку». They names the reel («графіка 2», «збери чернетку 3»); if they don't, check `review/<id>` of every reel in the index for a new `buildRequest` or new overlays.
- **Render queue.** On «збери чернетку» for a reel: import, snap_joins, `REEL_PREVIEW=1 cut.py`, precheck and fixes as usual, then `python3 scripts/render_queue.py add <reel> --preview` instead of render.sh, set its status to «рендериться», and start `python3 scripts/render_queue.py run` in the background (a second `run` exits by itself, so it is safe to start it every time). Renders run one at a time in the order added; re-adding a reel that still waits replaces its job. Never call render.sh directly during a batch: two renders at once slow both down and can freeze the Mac.
- **Each finished render:** watch `~/reels/.queue/done.log` (Monitor on new lines). On `DONE <reel>`: frame check, 540p proxy, upload, `builds/<id>`, status «чернетка готова», `PushNotification` with the reel's name. On `FAIL`: read the end of the render output, fix, re-add. `render_queue.py status` shows what is rendering and what waits.
- Final, covers, deliver and CapCut go reel by reel exactly as for a single reel; set status «фінал» when delivered.

## When they say "build preview"

**«Зібрати чернетку» with «Змінити» notes:** the press means «build the draft». Make every change they asked for and render the DRAFT straight away (`builds/<id>`, step 3 opens by itself); never stop at a new step-2 video and make the press the button again. A change they ask for in chat while on step 2 works the same way unless they say they only wants to see it first.

1. `ArtifactData get review/current` (save to a file). Missing is fine: it means "use the proposal".
2. `python3 scripts/review_sync.py import <reel> <review.json>` → `edl.json` + `edit.json`. Act on every `CHANGE REQUESTED`, `NOTE` and `REVISION` line it prints before rendering; `HOOK` / `CTA` lines are their approved text: use it word for word (it already went into the title / CTA card), don't ask again; for every `OVERLAY ...
