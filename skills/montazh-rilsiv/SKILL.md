# Reel editor

*Монтаж рілсів від [@inna_berezova](https://instagram.com/inna_berezova) (Інна Березова).*

Turns a raw talking-head clip into a finished, on-brand vertical reel. Every brand choice (colours, fonts, caption style, sounds, CTA) comes from the person's **brand file**, never from defaults baked into this skill. You do the editing; they only make the calls that are theirs.

## Before anything else: is there a brand file?

The workspace is `~/reels/` unless `REELS_HOME` is set.

- **No `~/reels/brand.md`** → first take what earlier course stages (TARGET AI) already made: the design system in Claude Design (colours, fonts with their files, logo) and `dyzain.md`, `profil.md`, `bryf.md`, `ca.md`, `keisy.md`. Read `references/setup-uk.md`, then Step 0 of `references/setup-interview.md`. Build the brand file from them and ask only what they don't say (one message, at most 4 short reel questions with a default each). Never ask what those files already answer, never ask for font files that are in the design system. The full interview is only for someone with none of these. Do not edit a clip without a brand file.
- **Brand file exists** → read `brand.md` and `brand.json` in full, then continue.

## Which style (before every edit)

Their editing style lives in `~/reels/styles/<name>.json` + `STYLE.md`, built in rounds on the review page's «Стиль» tab (`references/style-lab.md`, `scripts/style_lab.py`). Several styles per account are normal.
- **No styles yet** → offer the style lab once («Зберемо твій стиль монтажу? 9 варіантів на 5 секундах твого відео»); a no means brand.json alone, as before.
- **One style** → use it. **Several** → she picks it on the review page's «Графіка» tab («Стиль монтажу», before «Готово → Claude»); `review_sync.py import` prints `STYLE:` and writes `<reel>/style.txt` + edit.json `"style"`. Plan your graphics proposals in that style (read `style.txt` or her review doc's `style` before writing proposal.json). Not picked on the page: ask «Яким стилем монтуємо?» in chat (or use brand.json `"style"` as the default) and write the name to `<reel>/style.txt`. Read that style's `STYLE.md` section before planning graphics: its Відхилено list is a hard no.
- Never use someone else's style for a person: a student's styles come from their own rounds.
- **Two picks with no style file** (page buttons under the styles; `style.txt` holds the word):
  - `brand` («Тільки бренд»): their colours and fonts only, no style. Template cards in the brand look plus catalog motions at the usual count for brand.json `"graphics"`.
  - `mix` («Без стилю: мікс ефектів»): no style, the graphics come from the whole motion library. Plan it as: run `python3 scripts/motions.py ideas <reel>` and build the plan mostly from catalog motions: at least 6 different ones (8+ on a reel over 60 s), from at least 4 different moments (цифра, список, чат, до/після, ім'я, CTA...), freshest first, none twice, none from the last 3 reels if the catalog has another that fits; never two motions with the same layout (split / front / bubble / full) in a row. **Scenes, not plain text:** at least two thirds of the motions are ones `ideas` marks `[складне]` (phones, chats, notifications, charts, carousels, lower thirds, hand-drawn scenes, head layouts, 1-2 catalog transitions at a change of topic); `[просте]` text effects (one word or number animating) at most a third, never two in a row; build_reel prints `variety:` when a plan goes over. Keep every motion's text to 2-4 words. Template cards (split, push, list, camera) only for lines no motion fits, at most a third of the plan. The point of `mix` is that two reels never look alike: after each reel `motions.py log` so the next one reaches for others.
- **`minimal` («Мінімал»)**: the reels people make with memes and pictures: cut, captions, hook, CTA, at most one short text, and only the photos / GIFs / memes / b-roll THEY picked in «Накладення → Знайти». Claude adds no catalog motions, no camera moves, no cards. When their reel has picked finds and no style is chosen, propose `minimal` (one line), don't pile animations on top of their pictures.

## This is the Windows version
Everything runs in Claude Code's shell on Windows, which is Git Bash. Rules for every command in this skill:
- `python3` on Windows is often a Microsoft Store stub that does nothing. Wherever this skill says `python3 scripts/x.py`, run `python scripts/x.py` (or `py scripts/x.py` if only the launcher exists). The `.sh` scripts find the right Python themselves, and every script switches on UTF-8 itself (brand files and captions are Cyrillic).
- `~` is the person's user folder (`C:\Users\<name>`). The finished reels go to `~/Videos/Reels` (Відео → Reels).
- Face finding (`face_box.py`) uses OpenCV from `~/reels/.venv` instead of macOS Vision; `doctor.sh` installs it.

## First run on a new computer (do it yourself, never send the person to a terminal)
The person works in the Claude desktop app, Code tab. Never ask them to open PowerShell, CMD or a terminal. Windows asks «Дозволити цій програмі вносити зміни?» for some installs: tell them to click «Так». In this order, skipping what is already there:
1. Python: if `python -c "import sys"` fails (and `py -c "import sys"` too), run `winget install -e --id Python.Python.3.12 --scope user --accept-package-agreements --accept-source-agreements`.
2. Node.js: if `node -v` fails, `winget install -e --id OpenJS.NodeJS.LTS --accept-package-agreements --accept-source-agreements` (the «Так» window appears).
3. ffmpeg: if `ffmpeg -version` fails, `winget install -e --id Gyan.FFmpeg --accept-package-agreements --accept-source-agreements`.
4. A new install isn't on this shell's PATH yet. Append these lines to `~/.bashrc` (once) and also `export` them in every command until the app restarts:
   `export PATH="$LOCALAPPDATA/Programs/Python/Python312:$LOCALAPPDATA/Programs/Python/Python312/Scripts:/c/Program Files/nodejs:$LOCALAPPDATA/Microsoft/WinGet/Links:$PATH"` and `export PYTHONUTF8=1`. Then re-check `python`, `node`, `ffmpeg`. If one is still missing, find its .exe under `C:\Program Files` or `$LOCALAPPDATA` and add that folder.
   If `winget` itself is missing (old Windows 10), say so plainly and send them to the Microsoft Store page «App Installer» to update it, then continue.
5. `npx skills add heygen-com/hyperframes -g -y` if the HyperFrames skills are missing (`-g`: into the user folder, whatever folder the shell is in).
6. `bash scripts/setup_engine.sh` (animation library + sound effects).
6a. `bash scripts/setup_motion.sh` (the Remotion motion library in their brand: `~/motion` + the `motion-brand` skill, ~1 GB, a few minutes; it renders one test element). Run it again after the brand file exists (step «Before anything else»), so colours and fonts come from their brand: every render re-reads `brand.json` anyway.
7. Speech recognition: connect ElevenLabs Scribe (section «Connecting ElevenLabs Scribe» below). It is required: there is no local recogniser, so nothing large is downloaded. Walk them through creating the key in one short step at a time.
8. `mkdir -p ~/reels/fonts ~/reels/assets` (the reels workspace).
9. `bash scripts/doctor.sh` (it also installs font measuring and face finding into `~/reels/.venv`). If it's READY, tell them in one sentence that everything is ready, that it's worth closing and reopening the Claude app once (so the new programs are found), and that next time they open the Code tab with the folder `reels` and write «змонтуй рілс».
Explain each step in one short Ukrainian sentence: the person is a beginner.

## Check the tools (once per machine)

`bash scripts/doctor.sh` - checks ffmpeg, Node, the HyperFrames skills and (if the brand file says CapCut) the CapCut connector. Fix anything it flags before editing. Install steps are in the repo README.

## The edit, in order

Each reel gets its own folder: `~/reels/<yyyy-mm-dd>-<short-name>/`. Copy the raw clip in (never edit the original).

1. **Transcribe** - `python3 scripts/transcribe.py <clip> transcript.json`. Uses ElevenLabs Scribe with `ELEVENLABS_API_KEY` from `~/.config/reels/.env` (tight word timing; it writes "ем"/"um" as words, which is how fillers are found). There is no local fallback: exit code 2 = no key (connect it), 1 = key, balance or network problem (say which, then retry).
2. **Clean the voice** - `bash scripts/clean_audio.sh <clip> voice.wav` (add `--denoise` if there is background noise). Targets -14 LUFS, the level Instagram and TikTok expect.
**Face zone:** `python3 scripts/face_box.py <folder>` (OpenCV from ~/reels/.venv, ~30 s) before the review export, so graphics and captions keep off the face (see «Face, captions and «За мною»» in references/review.md).
3. **Review (their call)** - propose: lines to cut (repeats, false starts, rambles), fillers to drop, CTA moved to the end, target under 60 s, and the graphics plan. **Wait for their yes before cutting.** This is the step people care most about.
   **Look at the start and end before proposing cuts:** grab a frame every 0.5 s for the first and last 4 s. Cut any camera setup (pointing at the floor/garden, flipping the camera, reaching for the phone) even if words are spoken over it. Start on the first frame where they're settled in shot, and on a word that works as an opener.
   - **Main path: the Reel Review page.** ALWAYS run a tool search for `Artifact` and `ArtifactData` first (they are usually deferred and only appear after the search). Never decide they are missing without searching. If they do, follow `references/review.md`: they tap words to cut, watch the live rough cut, check graphics, captions, sound and colour, then say "build preview". Its import step writes `edl.json` + `edit.json`, so skip to step 4's cut and step 5.4's render.
   - **Step 2 («графіка»): video first.** Plan every effect locally (`proposal.json` → `export`), render the cut WITH them (`scripts/graphics_preview.py`), and only then write the board, the video (`builds/cut`, `rendered: true`) and `claudeRound` +1 to the page in one batch: no effect blocks on their page before the finished video. `reel/current` on round 1 always has `claudeRound: 0` (export writes it; never copy it from an older reel), and a «Зібрати чернетку» that arrives with no rendered step-2 video is a step-1 press: do round 2 first.
   - **Several clips at once (3-5):** one page with a reel picker and a render queue (`scripts/render_queue.py`): prepare reel 1 first and send the link, prepare the rest while they review, renders queue one at a time. See «Several reels at once» in `references/review.md`.
   - **Fallback: review in chat** only when the search found no such tools. Say so in one line first: «Сторінку перевірки відкрити не можу: в цій сесії немає інструментів Artifact/ArtifactData, тому перевіряємо в чаті». Show the transcript as numbered lines (format in `references/rough-cut.md`), then the card list in step 5.
4. **Tighten, then cut + speed** - write `edl.json` from the approved lines, then `python3 scripts/tighten.py <folder>`: it removes fillers and shortens pauses inside the kept lines, as hard as the brand's `"pacing"` says (`natural` default, `tight`, `fast`; presets in `scripts/pacing.py`). They never approve these one by one. Then `python3 scripts/snap_joins.py <folder>` (moves every join into the nearest quiet gap: transcript times are never exact, and a cut on them clips words), then `python3 scripts/cut.py <folder>`. Speed comes from the same preset unless `brand.json` sets `"speed"`.
5. **Graphics + captions: fill the template, don't design.** You are the editor here, not the designer - the look is already built from the brand file.
   1. `python3 scripts/transcribe.py master.mp4 master_transcript.json`
   2. `python3 scripts/auto_edit.py <folder>` → drafts `edit.json` (captions in their caption mode, punch-ins)
   3. Edit `edit.json` yourself, in one pass: set `"accent": true` on the one key word per sentence, and add cards at the density `brand.json` `"graphics"` asks for: `minimal` about one every 8-12 s, `balanced` (default) every 4-6 s, `busy` every 2-4 s, `inserts` = «врізки під кожну фразу» (one insert per phrase: real logos, live screenshots, their numbers; run `scripts/inserts.py <reel> --fetch` first and follow `references/inserts.md`; also when they ask for «врізки» on any reel). A line with nothing to show gets no card; don't chart every number or screenshot every tool just to fill the gap. Card types and fields are in the header of `scripts/build_reel.py`. Every card must show what that exact line says.
      - **Catalog motions, many and fresh.** 86 tested HyperFrames motions (text effects, counters, rings, charts, checklists, chats, ChatGPT/Claude screens, notifications, reviews, lower thirds with their name, CTA blocks, carousels, light leaks) are in `references/motion_catalog.json`. Run `python3 scripts/motions.py ideas <reel>` before planning: it offers 1-3 motions per phrase, freshest first. Each reel uses `minimal` 2+, `balanced` 4+, `busy`/`inserts` 6+ different ones, never one twice in a reel, preferably none from the last 3 reels. A motion is either fully clear of the face (front, behind, a rounded window) or it replaces the frame (split screen, full screen), never a panel half over the person. Card, layouts and fields: `references/motions.md`.
      - **Ефекти Vibha (42 more scenes, `fx-*` in the catalog).** orbit, spotlight, phone-fan, profile-wall, the-bill, tier-list, red-collage, led-sign, rabbit-hole and more, with face tracking and «behind you» cut-out: card `{"type": "fx", "fx": "orbit", "start", "end", "text", "opt"}`, rendered into the cut by `scripts/fx_pass.py` (render.sh runs it). Every text option gets the person's words, never the effect's English samples. Details: «Ефекти Vibha» in `references/motions.md`.
      - **Transparent motion elements.** A WebM with an alpha channel (VP8/VP9) or a ProRes 4444 MOV (Remotion `--codec=vp9 --pixel-format=yuva420p`, After Effects, any motion tool) goes in as an `overlay` card: drop it into `<reel>/overlays/` and add `{"type": "overlay", "src": "overlays/<name>.webm", "start": .., "end": ..}`. It plays over the whole frame with no border and no entrance of its own, and captions step aside for its seconds. It counts as one of the reel's motions. Details: «Transparent motion elements» in `references/motions.md`.
      - **Hook title: always ASK the person for the exact hook text before adding the title card. Never write or pick it yourself, not even from the transcript.** Text they typed in the hook / CTA fields on the review page («Графіка») IS their approved text: `review_sync.py import` prints it as `HOOK (their text, use as is)` / `CTA (their text)`; use it word for word and don't ask again. The hook stays on screen at least 3.5 s. Offer 3 options built from their own words in proposal.json `"hookOptions"` (the storyboard turns them into pictures A/B/C on «Графіка», next to the field for their own hook); the card goes in only with the text they picked or typed. Layout: max ~10 characters per line, 2-3 lines (`"still / uploading / screenshots?"`), so it renders big. It's the only text with an outline.
      - **No captions over an effect.** While any effect, card, head layout, brand element, name plate, full-screen or text graphic is on screen, the captions are hidden for those seconds: never a caption on top of a graphic, never one phrase left hanging under it. build_reel does it (every such card goes into its `quiet` spans; a catalog caption style gets those spans cut out of its own timeline). Only the person's own small photo / GIF in a corner, pure camera moves and transitions on a join (catalog `use: transition`, e.g. editorial-flash-overlay, light-leak) keep the captions (build_reel `KEEP_CAPS`). After every draft, grab a frame inside each graphic and check: no caption text on it; if there is, fix the card's `quiet` before showing it.
      - **Nothing else on screen while the hook is** (camera moves aside): plan no card or motion that starts inside the hook's window; core.js pushes any that does to right after the hook (`afterHook`).
      - **Carousel:** if `brand.json` has `"require_carousel": true`, every reel gets one (`motion` card, a `carousel-*` name, `images` from screenshots/their assets). If no line suits one, ask them; if they say no, set `"no_carousel_ok": true`.
      - **Screenshots:** for a tool or site they name that the line is about, run `bash scripts/screenshot.sh <url> shots/<name>.png`. Exit code 2 means the site blocked it: try the tool's marketing page, or ask them for a screenshot. Never use a blank one.
      - **Their own photos/videos come first.** They place them on the review page's «Накладення» tab (or drop files in the reel folder and say where) before you plan anything else; then your cards and motion go around them, never in the same moment and area (`review_sync.py overlays` lists them and flags CONFLICTs; two rounds, see `references/review.md`). Each becomes an `overlay` card (sizes small-r/small-l/big/full or a dragged `box`, effects soft/slide/polaroid/glass/zoom; header of `scripts/build_reel.py`).
      - **Pictures, GIFs, memes, b-roll only when THEY ask** (page «Накладення → Знайти», or chat «знайди…»). Never add them on your own and never pick for them. Ask what it must convey if they didn't say (an emotion, a state, a vibe). Then `python3 scripts/find_options.py <reel> <request id> photo|gif|video|meme "<english query>" ["<angle 2>" ...] -n 12` (10-15 options, English queries: the libraries index English tags), upload the `pv/` previews (asset: true), write `reel/current.finds = {<request id>: [{id: <asset id>, url, poster?, kind, label, source, license, file}]}` and reply in one line. They pick on the page; their picks become their overlays (`fromFind`, `file` = the full-quality original in `finds/`, import uses it). Rules: a GIF = one per moment, they drag where it sits; full-screen b-roll = one per moment; photos = several, one after another; a meme = a template they pick + THEIR text (`find_media.py meme --id … --text … --into …`, import prints `MEME`). Licences: Pixabay photos/videos also for ads; GIPHY and meme templates organic only. Keys not connected yet → section «Connecting picture search» below. AI inserts (Krea) only with brand.json `"ai_inserts": true` (off: it costs money).
      - **«За мною» (behind the person):** `"behind": true` on any card (text, sticker, photo, motion) puts it between the background and the person. The person is cut out locally with `npx hyperframes remove-background` ONLY for the windows of those cards (~13 s of work per second of video, cached in `<reel>/cutouts`, so re-renders don't redo it). On the page it's the «За мною» checkbox. Use it where it reads better, not on every card.
      - **`bigtext` card:** huge words in the head font (`{"type": "bigtext", "text": "big / words", "y": 330}`, "/" breaks lines), usually with `"behind": true` so they sit behind the head. Fields in the header of `scripts/build_reel.py`. Transparent PNGs (their elements) go in without a frame.
      - Mix the kinds: website shots, a colour block, a list card (`"glass": true` for liquid glass), a sticker from their assets, a `follow` card for the big moment, a counter or chart when they say a number.
      - **Variety: never the same look twice in a row.** Lists go in as `{"type": "list", "title", "rows", "layout"?}`: leave `layout` out and each list gets the next look in turn (`drop` big numbered words, `notes` phone-notes sheet that ticks, `stack` cards piling up, `card` the white UI card), never the one the previous list had. **Screen splits and push-ins are rare:** `split`, `push` and `steps` rearrange the whole frame, so a reel the person didn't ask for them in gets at most one of the three, and none when the previous reel already had one; they are never the main graphic of a reel and never stand in for a list that came out small (fix the list instead). A split frames the person by face.json (the video slides so the face sits in the window, never the ceiling and the top of the head). For variety beyond lists: `split` (screen divides: brand panel with the list on top, the person slides into the bottom half; `"side": "left"` for left/right), `push` (наїзд кадру: a brand panel pushes the camera out, big words + rows, then the camera comes back from the other side) and `steps` (step panels slide up over each other, the one underneath steps back). Fields in the header of `scripts/build_reel.py`. build_reel prints `variety:` when three graphics in a row look the same: swap one.
      - **Camera moves are graphics too:** `{"type": "camera", "move": ...}`: `out` (starts close, pulls back: a new thought), `in` (slow push-in while they build up to a point), `whip` (fast zoom hit on a punch word), `shrink` (the frame pulls back into a rounded window on the brand colour with `"text"` above: a number or credential), `shake` (a jolt on a hard word). Use 2-4 per reel alongside the cards, and reach for the catalog motions (`scripts/motions.py menu`) instead of repeating one card type.
      - **Подачі голови (head layouts):** `{"type": "head", "look": ..., "words": [...]}`: for one phrase their own video shrinks into a window, circle, cloud, soft-edged frame, polaroid, collage tile... on a brand background, and their words from that phrase appear around it as they say them; the frame comes back by itself. 11 looks (effects menu №299-309): `window`, `circle`, `cloud`, `soft`, `polaroid`, `bigword`, `top`, `collage`, `pile`, `around`, `picture`. Use them on phrases that list things or land a key word; 2-5 different looks on consecutive phrases make the «rearranged talking head» rhythm. collage / pile / picture need THEIR photos. Looks, fields and rules: «Подачі голови» in `references/motions.md`.
      - **Real interfaces keep their own look:** catalog motions marked «інтерфейс, свої кольори» (`keep_ui`: phone chats, notifications, iOS, X, ChatGPT screens) render in their native colours and system font, never repainted in the brand palette; a full-frame one dims the video with neutral black.
      - **Never cover the face.** `list` and `steps` read `face.json` and move below the chin (or above the head), shrinking only if they must. `split` frames the person from just above the head down and gives them 60% of the screen (`"panel"` sets the brand panel's height, default 760). Every card is placed on the words it illustrates: put rows on `row_times` at the spoken word.
      - **Safe zones:** build_reel checks every card and caption against Instagram's Reels screen (top bar 0-220, buttons right x 950+ y 1000-1500, nick and caption below 1500, side strips 60 px cropped on tall phones) and prints `safe zone:` lines (also in `<reel>/safezones.json` and qa.py). Fix each one in `edit.json` (move `y`, shorten text) before the draft. On the review page the «Зони» button lays the same screen over the video.
   4. **Before the first render, always:** `python3 scripts/precheck.py <folder>`. It hears `master.mp4` again, re-times captions/cards/punch-ins to it, and lists every JOIN (read each: no clipped, doubled or stray word), MISSING speech with no caption, and CHECK words the caption has wrong (misheard words: fix the spelling to what they said). Fix all of it in `edit.json` (a bad join: edl + snap_joins + cut, then precheck again) so the draft they see is already right. A render takes ~6 min: never render to find these.
   4a. **Effects check, before EVERY render (2026-10-26: a wrong effect found on the draft costs a second render):** `python3 scripts/fx_check.py <folder>` (~30 s for 10 graphics). It checks every card's text (black list, fields the motion doesn't have, lists with «|» where it wants commas, the motion's own test numbers like 42, English samples and someone else's nick, long text on one-line effects, English baked into the effect's HTML) and makes one still per graphic at its peak, on their cut, in their brand: `check/sheet.jpg`. Fix every ERROR, then LOOK at the sheet: text inside the frame, readable and big enough, only their words and their numbers, face clear, nothing tiny or dim. Fix what looks wrong and run it again. render.sh refuses to start while the graphics changed since the last clean check (exit 3; `REEL_NO_CHECK=1` only for a reel with no new graphics). The fx pieces it makes are the same cache render.sh uses, so nothing renders twice. A render is never how we find a wrong effect.
   - **Their black list** `<REELS_HOME>/blacklist.json` (`{"items": [{"name", "why", "date", "rebuild"?}]}`) grows reel by reel: an effect they reject («не подобається», «погано виглядає») or one whose still is tiny / dim / unreadable on their video goes in with the reason in their words. `motions.py ideas` never offers them, fx_check stops on them. `rebuild: true` = they like the idea but not the look: it comes back only rebuilt the way they asked (then remove the item).
   5. Drafts: `REEL_DRAFT=1 REEL_PREVIEW=1 bash scripts/render.sh <folder>` → `draft.mp4` at 540x960 (a quarter of the pixels, from a 540p copy of the master; final.mp4 untouched). Fast, for review only; every notes round renders a new draft. **The final renders once**, after they approve: `REEL_PREVIEW=1 bash scripts/render.sh <folder>` (1080x1920, or `--final` for a 4K brand) → `final.mp4`, then QA and deliver. On an 8 GB computer keep `REEL_WORKERS=1` for the final: two Chrome workers run out of memory, time out and redo the frames.
   6. **When a render finishes, send a phone notification** (`PushNotification`; run a tool search for it first, it is usually deferred): reel name + what to check. `render.sh` only shows a Windows notification, and they may be away from the screen.
   Do **not** hand-write composition HTML or use other HyperFrames workflows here: they are slower and ignore the brand template. Exceptions: own motion design on a phrase or sentence (see "Own motion design on phrases" below) goes in as a `custom` card; a ready transparent motion element goes in as an `overlay` card.
6. **QA** - `python3 scripts/qa.py <folder>` (loudness, size, length, missing words). Then grab a frame at every card and look: text inside the frame, readable over the background, on brand. Fix `edit.json` and re-run render.sh until it passes.
7. **Deliver** - `bash scripts/deliver.sh <final.mp4> "<clear name>"` → upload-ready MP4 in their delivery folder. Then `python3 scripts/motions.py log <reel>` so the next reels reach for other motions, and `python3 scripts/motions.py stamp <reel>` («Мої марки»: every graphic the finished reel kept goes into `<REELS_HOME>/stamps.json` with a still from the reel; upload new stills from `<REELS_HOME>/stamps/` to the page and map them in `.motion_previews.json` as `"stamp:<id>"`). `motions.py ideas` offers their stamps first (★ моя марка), with the settings that worked.
   **Covers** (skip when brand.json `"covers": false`): then `python3 scripts/cover.py <reel> ["hook / text"]` → `cover_1.jpg`..`cover_3.jpg` + `covers.jpg` side by side: the sharpest camera frames from three parts of the reel with the approved hook in the brand's head font, text off the face and inside the 4:5 area the profile grid shows. Show `covers.jpg` and let them pick. The hook text is theirs (argument or the title card); never invent it.
7a. **Instagram** (page button «Опублікувати в Instagram» on the final = `publishRequest` with their caption in `S.igCaption`; or they ask in chat): needs the Meta connector in Claude (Settings → Connectors). Confirm in one line the account (`get_instagram_accounts`) and the caption, wait for their yes, then `python3 scripts/publish_ig.py final.mp4 [cover.jpg]` (a 1-hour public link: Instagram only fetches public URLs, the page's files are private) → `publish_instagram_media` (REELS, `share_to_feed: true`, `skip_if_recently_published: true`) → write `published: <permalink>` into `builds/latest`. Never post without that yes.
8. **CapCut** - `brand.json` `"capcut"`: `true` = always build the CapCut draft; `"ask"` = after delivering the MP4, ask once «Відправити ще в CapCut?» and build it only on a yes; `false` = never. Building it means one extra render with `--capcut` (no captions/sfx baked in), then `references/capcut.md`.

Tell them what changed, and what to check by ear (cuts, names, brand words spelled right).

## Own motion design on phrases
Besides the template cards, the person can ask for their own motion on a phrase or sentence: over the video, or a full-screen takeover that covers them for a few seconds. Offer it in the graphics plan where a line deserves it; they decide.
- If they already have the element as a transparent video (Remotion, After Effects...), use it as an `overlay` card instead of writing a new composition.
- Effects, rules and timings: `references/motion-effects.md`. Colours and fonts come ONLY from `~/reels/brand.json` / `brand.md`.
- Build each one as a HyperFrames sub-composition in `<reel>/motion/<name>.html` (1080x1920 unless boxed; own `data-composition-id`, `data-width`, `data-height`; GSAP timeline registered in `window.__timelines["<id>"]`, seek-safe; copy the brand font files and `engine/gsap.min.js` next to it). Use the `hyperframes` skill for authoring.
- Time it on `master_transcript.json` (the cut reel), then add to `edit.json`: `{"type": "custom", "src": "motion/<name>.html", "start": .., "end": .., "layer": "front", "full": true|false, "sfx": "whoosh"}`. Full-screen takeovers set `"full": true` (captions step aside).
- Text behind the head / card behind the person: set `"behind": true` on the card (see «За мною» in step 5.3); the cutout runs only on those windows and is cached. Say it adds a few minutes before the first render with it.
- Before the draft, grab a frame at the peak of every custom motion and check it.

## Connecting picture search (optional, once: Pixabay + GIPHY, free)
Only when they first ask for photos / videos / GIFs / memes (memes need no key). One short step at a time, in Ukrainian:
1. **Pixabay** (photos and videos, free, also for ads): pixabay.com → sign up / log in → pixabay.com/api/docs → their key is in the «key» line of the example. Then run `bash scripts/set_key.sh PIXABAY_API_KEY`: a Windows sign-in style window opens, they paste the key into the password field and press OK. Never ask them to paste a key into the chat.
2. **GIPHY** (GIFs, organic posts only): developers.giphy.com → log in → Create an App → API → name and description anything → copy the API Key → `bash scripts/set_key.sh GIPHY_API_KEY`.
Keys live in `~/.config/reels/.env` (only on their computer). `bash scripts/doctor.sh` shows which are connected.

## Connecting ElevenLabs Scribe (required, once)
Scribe gives exact word timing and hears "е/ем"; under 2 cents a reel ($0.22 per hour of audio, ElevenAPI tab → Add credits; keep Auto Top Up off).
1. They create a key at elevenlabs.io → Developers → API Keys → Create: Restrict Key on, only **Speech to Text = Access**, everything else No Access. The real key starts with `sk_` and is shown once (the key ID is not the key).
2. Never ask them to paste it in chat. Open the masked Windows dialog, which writes it straight to `~/.config/reels/.env` and prints only its length:
   `powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$(cygpath -m scripts/ask_key.ps1)"` (a Windows sign-in style window: they paste the key into the password field and press OK). `SAVED` = done; `NOT A KEY` = they pasted the key ID, ask for the `sk_` key; `CANCELLED` = ask again.
3. Test it on 20 s of audio with `scripts/transcribe.py` (it should say "transcribed with ElevenLabs"). A bad key stops transcription with a clear message: fix the key or the balance, never work around it.

## Language
`brand.json` "language" (e.g. `"uk"`) drives transcription, filler words and QA. Talk to the person in their language. The Reel Review page UI is in Ukrainian: write every `kind` and `what` in proposal.json in Ukrainian too, and treat «збери чернетку» as "build preview", «фінал» as "final" and «стиль» as "the style round is rated" (`references/style-lab.md`).
Transcription is ElevenLabs Scribe for every language; fillers are hesitation sounds only (е, ем, ммм, хм; "ну" only on tight/fast pacing).

## Their brand rules win

If the brand file and your taste disagree, the brand file wins. If they correct something during an edit ("no, never outline captions"), add it to `brand.md` under "Rules" straight away so the next edit gets it right.

## Common mistakes

| Mistake | Instead |
|---|---|
| Editing before a brand file exists | Run the setup interview |
| Cutting on transcript word times blindly | `snap_joins.py` before `cut.py`, then read the JOIN lines from `precheck.py` |
| Finding wrong words or late captions on the draft or final | `precheck.py` before the first render; one draft + one final is the target |
| Graphics that decorate instead of illustrate | Each card shows what this exact line says |
| Captions in a font the brand file bans | Re-read brand.md "Rules" before step 5 |
| Saying CapCut works everywhere | It doesn't (see capcut.md). The MP4 route always works |
| Finding a wrong effect on the rendered draft (a second render) | `fx_check.py` stills before every render; render.sh refuses without them |
| Fixing QA failures by lowering the bar | Fix the edit, re-run QA |
